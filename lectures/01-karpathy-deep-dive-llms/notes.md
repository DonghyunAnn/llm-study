- 강의: Andrej Karpathy, [Deep Dive into LLMs like ChatGPT](https://www.youtube.com/watch?v=7xTGNNLPyMI) (2025-02, 3h31m)
- 정리 방식: 자동 생성 영어 자막 기반. 화면에 나온 도표, 데모 화면, 논문 캡처는 보지 못했고, 자막에서 언급된 내용만 반영했다. 용어 오타(예: "Chachi PT")는 문맥으로 교정했다. 자막 밖에서 보충한 정보(영상 설명란, 논문)는 "(설명란)" "(논문)" 또는 "(보충)"으로 표시했다.
- 성격: 코드 없는 개념 강의. 세 단계 학습 파이프라인(pretraining → SFT → RL)과 그로 인한 모델의 "심리"를 다룬다. 강의 repo는 없다.
- 검수: 초안을 Claude 서브에이전트와 Codex CLI가 독립적으로 자막·코드와 대조해 리뷰했고, 지적을 근거로 판정해 반영했다.

## 한 줄 요약

ChatGPT에 질문을 넣고 엔터를 치면 돌아오는 것은 **OpenAI가 고용한 라벨러를 신경망으로 시뮬레이션한 결과**다. 단, thinking 모델(o1/o3, DeepSeek-R1)은 RL로 스스로 발견한 사고 전략이 더해져 있어서 단순한 라벨러 모방을 넘어선다.

## 1. Pretraining: 인터넷을 압축하기

### 1.1 데이터 (0:01–0:07)

- 출발점은 Common Crawl (2007년부터 크롤링, 2024년 기준 27억 페이지). 여기서 시작해 여러 단계로 필터링한다.
- FineWeb (HuggingFace)이 대표적인 공개 사례. 필터링 후 **44TB, 15조 토큰**. 인터넷 전체가 아니라 텍스트만, 그것도 공격적으로 걸러낸 결과라 하드디스크 하나에 들어가는 크기다.
- 필터링 단계: URL 차단 목록(스팸, 성인, 악성) → HTML에서 본문 텍스트 추출 → 언어 분류(FineWeb은 영어 65% 이상만) → 중복 제거 등 몇 단계 → PII 제거.
- 언어 필터는 설계 결정이다. 스페인어를 다 버리면 모델은 스페인어를 못한다. 다국어 성능은 회사마다 다르게 가져간다.

> minimind는 이 단계를 건너뛴다. 정제된 jsonl을 받아서 시작한다. 데이터 파이프라인은 CS336 4단원에서 보강.

### 1.2 토크나이저 (0:07–0:15)

- 신경망은 **유한한 기호 집합의 1차원 시퀀스**를 원한다. 텍스트를 어떤 기호로 표현할지 정해야 한다.
- 선택지의 스펙트럼: bits (2개 기호, 매우 긴 시퀀스) → bytes (256개, 8배 짧음) → BPE (수만~수십만 개, 더 짧음).
- **시퀀스 길이는 비싸고 귀한 자원**이라 기호 수를 늘려 길이를 줄이는 쪽으로 간다.
- BPE: 가장 자주 붙어 나오는 바이트 쌍(예: 116, 32)을 새 기호(256)로 만들고 치환. 반복. GPT-4는 100,277개 토큰.
- 토큰은 숫자가 아니라 **고유 ID**로 생각해야 한다. 이모지로 바꿔 생각해도 무방하다.
- 같은 텍스트라도 대소문자, 공백 수에 따라 토큰이 달라진다("hello world" ≠ "Hello World" ≠ "hello  world"). 이것이 뒤에 나오는 철자 문제의 원인이 된다 (§3.4 참조; 강의자도 "토크나이저는 나중에 다시 돌아온다"고 예고).

> minimind는 vocab 6400. 강의에서 말하는 "기호 수 vs 시퀀스 길이" 트레이드오프를 작은 모델 쪽으로 극단화한 선택이다. 임베딩과 출력층이 파라미터의 큰 비중을 차지하므로 vocab을 줄였다(README 참조). 상세는 "Let's build the GPT Tokenizer"에서.

### 1.3 학습 (0:15–0:26)

- 데이터에서 토큰 윈도우를 무작위로 뽑는다. 길이는 0부터 최대 컨텍스트(예: 8,000)까지. 더 길게도 할 수 있지만 연산이 비싸서 자른다.
- 입력: 컨텍스트 토큰들. 출력: 어휘 크기만큼의 숫자 = 다음 토큰의 확률.
- 초기 모델은 랜덤이라 확률도 랜덤. 정답 토큰(라벨)의 확률은 올리고 나머지는 내리도록 파라미터를 조금씩 조정한다. 이것이 학습이고, 배치로 병렬 수행한다.
- 파라미터는 DJ 믹서의 노브에 비유. 학습 = 훈련 데이터의 통계와 일치하는 노브 설정을 찾는 것.
- Transformer: 곱셈, 덧셈, 지수, 나눗셈이 섞인 하나의 큰 수식. 상태(memory)가 없는 순수 함수다. 생물학적 뉴런과 비교하면 훨씬 단순하다. 카파시는 내부 수학 세부는 "그렇게 중요하지 않다"고 말하고 넘어간다.
  - 구성 요소 언급: 임베딩(토큰 → 벡터) → layer norm, 행렬곱, softmax → attention 블록 → MLP 블록 → logits/softmax.

> `model_minimind.py`가 정확히 이 수식이다. 287줄. 강의가 넘어간 "내부 수학"을 코드로 보는 게 minimind 실습의 목적.

### 1.4 추론 (0:26–0:31)

- 프리픽스 토큰을 넣고 확률 분포를 얻어 **편향된 동전 던지기**로 하나를 뽑는다. 붙이고 반복.
- 확률적이라 같은 프리픽스에도 매번 다른 결과. 훈련 데이터의 조각을 그대로 재현하기도, 어디에도 없던 시퀀스를 만들기도 한다. "훈련 데이터의 리믹스".
- 데이터 다운로드·토큰화는 한 번, 학습은 여러 설정으로 여러 번, 최종 모델은 추론만. ChatGPT와 대화하는 것은 몇 달 전 학습된 고정 파라미터로 추론하는 것이다.

### 1.5 GPT-2 재현과 연산 (0:31–0:43)

- GPT-2 (2019): 1.5B 파라미터(강의 초반에는 1.6B라 했다가 뒤에서 정정), 컨텍스트 1,024, 약 1,000억 토큰 학습. 지금 기준으로 전부 작지만 **현대적 스택이 처음 완성된 모델**. 이후는 모두 "더 크게"다. 현대 모델은 파라미터 수천억~1조, 컨텍스트 수십만~100만 토큰.
- 재현 비용: 2019년 약 $40,000 → 카파시의 llm.c 재현은 하루, 약 $600. 더 줄이면 $100. 이유는 데이터 품질, 하드웨어, 소프트웨어 최적화.
- 학습 화면: 한 줄 = 한 번의 업데이트 = 100만 토큰에 대한 예측 개선. 7초/스텝, 32,000스텝 = 약 330억 토큰. 지켜보는 숫자는 **loss** 하나. 20스텝째 출력은 완전한 랜덤, 420스텝째는 지역적으로만 그럴듯한 횡설수설.
- 8×H100 노드, GPU당 $3/시간. 행렬곱의 병렬성 때문에 GPU가 적합. Nvidia 시총 $3.4조, 일론 머스크의 10만 GPU 데이터센터(xAI, 보충) 등이 전부 "다음 토큰 예측"을 위한 것.

> minimind 64M 모델을 3090에서 mini 데이터로 학습하면 약 1.2시간. 강의의 loss 화면과 같은 로그를 `train_pretrain.py`가 찍는다. "Let's reproduce GPT-2"가 이 부분의 코드판.

### 1.6 Base 모델의 정체 (0:43–1:00)

- base 모델 = **인터넷 텍스트 토큰 시뮬레이터**. 그 자체로는 어시스턴트가 아니다. 릴리스에는 두 가지가 필요: forward pass를 기술한 코드(수백 줄)와 파라미터(GPT-2는 15억 개 숫자).
- Llama 3.1 405B base (15조 토큰 학습)를 hyperbolic에서 시연:
  - "What is 2+2"를 넣으면 답처럼 시작하다가 곧 관련 없는 인터넷 문서처럼 흘러간다. 매번 다른 결과. **비싼 자동완성**.
  - 405B 파라미터는 인터넷의 zip 파일 같지만 무손실이 아닌 **손실 압축**. 남는 것은 인터넷의 "gestalt". 자주 나온 것은 잘 기억하고 드문 것은 흐릿하다.
  - **암기(regurgitation)**: 위키백과 Zebra 문서 첫 문장을 넣으면 한동안 그대로 암송. 고품질 소스는 여러 epoch(약 10번) 학습하기 때문. 바람직하지 않은 현상.
  - **환각**: 지식 컷오프(2023년 말) 이후 사건(2024년 선거)을 물으면 그럴듯한 평행우주를 만든다.
  - **In-context learning**: 영어-한국어 단어쌍 10개를 주면 패턴을 읽고 번역기 역할을 한다. few-shot 프롬프트.
  - **프롬프트만으로 어시스턴트 만들기**: "AI 어시스턴트와 인간의 대화" 형식의 few-shot 프롬프트를 주면 base 모델도 답을 한다(그 프롬프트 자체를 ChatGPT에게 써 달라고 했다). 다만 답 뒤에 다음 human 질문까지 환각한다.
- base 모델 공개가 드문 이유: 그 자체로는 쓸모가 적고, 전체 파이프라인의 1단계일 뿐이기 때문. GPT-2와 Llama 3.1 405B가 공개된 예외.

## 2. Post-training ①: SFT — 라벨러를 모방하기 (1:00–1:20)

- 사전학습은 수천 대 컴퓨터로 3개월, post-training은 3시간 정도. 데이터가 훨씬 작기 때문. **알고리즘은 동일하고 데이터셋만 바뀐다**: 인터넷 문서 → 대화.
- 어시스턴트는 코드로 프로그래밍하지 않는다. **대화 예시로 암묵적으로 프로그래밍**한다. 라벨러가 프롬프트와 이상적 응답을 쓰고, 모델이 이를 모방한다.
- 대화의 토큰화: 인터넷 프로토콜(TCP/IP)처럼 구조화된 객체를 1차원 토큰 시퀀스로 인코딩하는 규칙이 필요하다. GPT-4o의 예: `<|im_start|>user<|im_sep|>...<|im_end|>`. `im_start` 같은 특수 토큰은 사전학습 때 없던 **새 토큰**을 post-training에서 추가한 것. 2턴 대화가 49토큰.
- 추론 시: 서버가 `<|im_start|>assistant<|im_sep|>`까지 채우고 그 뒤를 샘플링한다.
- InstructGPT (2022): Upwork/Scale AI에서 라벨러 고용. 라벨링 지침의 핵심은 helpful, truthful, harmless. 실제 지침은 수백 페이지.
- 현재는 사람이 처음부터 쓰는 경우가 드물다. LLM이 초안을 쓰고 사람이 편집. UltraChat 등 대부분 합성 데이터인 수백만 대화의 SFT 믹스처.
- **핵심 관점**: ChatGPT의 답은 마법의 AI가 아니라 **라벨링 지침을 따르는 (꽤 숙련된) 라벨러의 통계적 시뮬레이션**이다. 파리 랜드마크 5개를 물으면, 라벨러가 20분 검색해 만들었을 답의 시뮬레이션이 나온다. 학습셋에 없는 질문이면 사전학습 지식과 결합해 창발적으로 답한다.

> minimind: `SFTDataset`이 이 인코딩을 한다. `<|im_start|>assistant\n`부터 `<|im_end|>`까지만 라벨을 살리고 나머지는 -100으로 마스킹한다. 즉 라벨러(assistant) 발화만 모방하도록 학습한다. `pre_processing_chat`이 20% 확률로 system 프롬프트를 섞는 것도 강의 후반 "자아 인식" 부분과 연결된다. minimind 토크나이저도 `<|im_start|>`/`<|im_end|>`를 쓰고, GPT-4o의 `<|im_sep|>` 자리는 개행(`role\n`)이다.

## 3. LLM 심리학 (1:20–2:07)

학습 파이프라인이 만들어내는 창발적 인지 효과. 강의에서 가장 실용적인 부분.

### 3.1 환각과 두 가지 완화책 (1:20–1:40)

- **원인**: 학습셋의 "Who is X?" 질문은 전부 자신 있는 어조로 답한다. 모델은 검색을 하지 않는 **"statistical token tumbler"**(강의자의 표현)일 뿐이다. 모델 내부에 "모름"을 나타내는 뉴런이 있더라도, 그것이 "모른다"는 **말**과 연결되어 있지 않다. 그래서 통계적으로 가장 그럴듯한 답을 지어낸다. Falcon-7B에 가상의 이름을 물으면 매번 다른 직업을 만들어낸다.
- **완화 1: "모른다"를 가르치기** (Llama 3 방식)
  1. 학습 문서에서 문단을 뽑아 LLM으로 사실 질문·답 생성.
  2. 모델에 같은 질문을 여러 번(3~5회) 물어 LLM judge로 정답과 비교.
  3. 계속 틀리면 그 질문에 "죄송하지만 기억나지 않습니다"를 답으로 하는 대화를 학습셋에 추가.
  - 이렇게 하면 내부의 불확실성 뉴런과 "모른다"는 출력이 연결된다. 질문 생성, 답 비교, 데이터 추가 전부 LLM이 하므로 사람 개입 없이 자동화 가능.
  - 시연: 최신 ChatGPT에 도구를 끄고 같은 가상 인물을 물으면 "그런 인물을 모른다"고 답한다. Hasek의 컵 수는 기억으로 "2회"라 답하고, 검색을 시키면 위키백과를 인용해 같은 답을 낸다.
- **완화 2: 도구 사용**
  - 파라미터 속 지식 = **한 달 전에 읽은 것의 흐릿한 기억**. 컨텍스트 윈도우 = **작업 기억**. 사람이 모르면 검색하듯 모델도 검색하게 한다.
  - 새 특수 토큰 `<search_start>` 질의 `<search_end>`를 도입. 추론 프로그램이 이 토큰을 보면 생성을 멈추고 검색 결과 텍스트를 컨텍스트에 붙여 넣는다. 그 뒤로는 검색 결과를 직접 참조.
  - 가르치는 방법은 역시 데이터. 몇천 개의 예시면 충분. 사전학습으로 "검색"이 뭔지 이미 알기 때문.
- **실용 교훈**: 특정 텍스트를 다루게 할 때는 기억에 의존시키지 말고 **컨텍스트에 넣어라**. "오만과 편견 1장 요약해줘"보다 1장 본문을 붙여 넣는 편이 훨씬 낫다.

### 3.2 자아 인식 (1:41–1:46)

- "너는 어떤 모델이야? 누가 만들었어?"는 사실 무의미한 질문. 모델은 지속적 자아가 없다. 대화마다 부팅되고 토큰을 처리하고 꺼진다.
- 명시적으로 가르치지 않으면 통계적 최선의 추측을 한다. Falcon이 "OpenAI가 만들었다"고 답하는 것은 OpenAI 데이터로 학습해서가 아니라 인터넷에 ChatGPT 관련 텍스트가 많기 때문일 가능성이 높다.
- 고치는 법 두 가지: ① OLMo처럼 정체성 대화 240개를 SFT 믹스처에 하드코딩. ② system message로 매 대화에 정체성·컷오프를 주입.

> minimind는 `SYSTEM_PROMPTS`(10개 중 5개가 "minimind"를 언급)를 **학습 데이터**에 20% 확률로 system 역할로 섞는다. ①과 ②의 중간 형태다. 추론 시 system message를 주입하는 ②는 `eval_llm.py` 기본값에 없다. ①의 minimind판은 README의 `lora_identity` 예제(정체성 데이터로 LoRA 학습)다.

### 3.3 모델은 생각할 토큰이 필요하다 (1:46–1:58)

- 토큰 하나를 예측하는 데 쓰이는 연산은 **레이어 수만큼으로 거의 고정**되어 있다(예: 100층. 컨텍스트가 길수록 약간 늘지만 무시할 수준). 한 토큰에 임의로 많은 계산을 욱여넣을 수 없다.
- 라벨링 예시: "사과 3개, 오렌지 2개, 오렌지 $2, 합계 $13, 사과 값은?"
  - 나쁜 라벨: "답은 $3입니다. 왜냐하면..." — `3`이라는 토큰 하나에 모든 계산을 요구. 뒤의 설명은 이미 나온 답의 사후 정당화.
  - 좋은 라벨: "오렌지 합계 4, 13-4=9, 9/3=3" — 계산을 여러 토큰에 분산. 각 토큰은 쉬운 문제만 풀고, 마지막에는 중간 결과가 작업 기억에 있다.
- ChatGPT가 "변수를 정의하고 식을 세우자"며 천천히 푸는 중간 계산은 **사용자용이 아니라 모델용**이다. 그것 없이는 답에 도달하지 못한다.
- 실험: 숫자를 키우고(사과 23개, 오렌지 177개) "한 토큰으로 답해"라고 하면 오답 $5. 제한을 풀면 중간 계산을 거쳐 정답 $7.
- 실무 교훈: 암산을 믿지 말고 **"use code"**로 Python 인터프리터를 쓰게 하라.

### 3.4 세기, 철자, jagged intelligence (1:58–2:07)

- **세기**: 점 177개를 세라고 하면 틀린다(161). 한 토큰에 세기를 요구하기 때문. "use code"를 쓰면 맞는다. 이유가 미묘하다: 모델은 세기는 못하지만 **복사-붙여넣기는 잘한다**. 점들을 문자열로 복사해 `.count()`를 호출하면 Python이 센다.
- **철자**: 모델은 문자를 보지 않고 토큰을 본다. "ubiquitous"는 3토큰. 매 3번째 글자를 뽑으라면 실패. 토큰은 효율을 위한 것이고 문자/바이트 단위 모델을 원하는 사람이 많지만 시퀀스가 너무 길어진다. 역시 코드로 우회.
- **strawberry의 r 개수**: 문자를 못 보는 문제 + 세기 문제의 결합. 지금은 맞추는데, 카파시는 OpenAI가 이 질문을 하드코딩했을 수도 있다고 본다.
- **9.11 vs 9.9**: 올림피아드 문제는 풀면서 이건 틀린다. 활성값을 분석한 팀에 따르면 성경 구절 관련 뉴런이 켜진다(성경에서는 9.11이 9.9 뒤에 온다). 완전히 이해되지 않은 사례.
- **jagged intelligence**: 대부분의 영역에서 뛰어나지만 예측 불가능하게 구멍이 뚫려 있다. 마무리(3:08)에서는 이를 **스위스 치즈 모델**이라 부른다. 도구로 쓰고, 검증하고, 결과물의 책임은 사람이 진다.

## 4. Post-training ②: RL — 스스로 연습하기 (2:10–2:48)

### 4.1 교과서 비유 (2:11–2:14)

| 교과서 | 학습 단계 |
|---|---|
| 본문 설명 (exposition) | Pretraining: 배경지식 축적 |
| 풀이가 있는 예제 | SFT: 전문가 풀이 모방 |
| 답만 있는 연습문제 | RL: 직접 풀어보고 맞은 방법을 강화 |

사람은 챕터마다 세 가지를 섞어서 하지만 LLM은 단계별로 한다. 회사 안에서도 사전학습 데이터, 사전학습, SFT 대화 생성, RL이 각각 다른 팀이고 모델을 순서대로 넘겨받는다.

### 4.2 왜 SFT만으로는 부족한가 (2:14–2:20)

- 같은 문제에 대한 정답 풀이 4개가 있을 때, 라벨러는 **어느 것이 모델에게 최적인지 모른다**.
- 사람에게 쉬운 것과 모델에게 쉬운 것이 다르다. "(13-4)/3="처럼 한 토큰에 두 연산을 요구하는 도약은 모델에게 너무 크고, 사람이 장황하게 쓴 부분은 모델에겐 낭비다. 반대로 모델은 박사급 지식을 갖고 있어 사람이 넣은 설명이 오히려 방해일 수도 있다.
- 결론: 모델이 **자기에게 맞는 토큰 시퀀스를 스스로 발견**해야 한다. SFT는 정답 근처로 보내는 초기화 역할.

### 4.3 RL의 핵심 루프 (2:20–2:28)

1. 프롬프트 하나에 수천~수백만 개의 풀이를 샘플링.
2. 정답과 비교해 채점(초록/빨강).
3. 잘 된 풀이(최단, 가장 깔끔한 것 등 기준은 다양)로 학습 → 그 경로의 확률이 올라간다.
4. 수만 개 프롬프트에 대해 반복. (데모는 Gemma 2 2B로 했는데 이 문제는 너무 쉬워서 항상 맞췄다. 카툰 예시는 15개 중 4개 정답.)

"guess and check". 학습 데이터가 라벨러가 아니라 **모델 자신**에게서 나온다.

- Pretraining과 SFT는 수년째 표준이지만 RL 단계는 아직 초기이고 비표준. 핵심 아이디어는 단순하지만 어떤 풀이를 고를지, 얼마나 학습할지, 프롬프트 분포 등 세부 사항이 많다. 회사들이 내부적으로만 하다가 **DeepSeek-R1 논문**("아주 최근"; 2025-01, 설명란)이 세부를 공개해 관심을 재점화했다.

### 4.4 DeepSeek-R1: 사고의 창발 (2:28–2:41)

- 수학 문제 정확도(논문 Figure 2의 AIME; 자막에서는 벤치마크명 식별 불가)가 RL 스텝에 따라 계속 오른다.
- 동시에 **응답 길이가 늘어난다**. 모델이 "wait, wait, that's an aha moment", "let me re-evaluate step by step" 같은 것을 하기 시작한다. 재검토, 다른 관점, 되돌아가기.
- 이건 사람이 라벨에 하드코딩할 수 없는 것이다. 사람 머릿속에서 일어나는 일이지 풀이에 적는 것이 아니기 때문. **정답만 주었는데 사고 사슬(chain of thought)이 최적화에서 창발**했다.
- R1 데모: 사과 문제에 "let me check my math again... let me see if there's another way... setting up an equation... yep same answer" 후 사람용 정리 답안. 정확성(사고)과 표현(정리)이 분리된다.
- OpenAI o1/o3는 같은 방식으로 학습됐다고 직원들이 공개 발언. 다만 사고 사슬을 요약만 보여준다(증류 위험). GPT-4o는 "대체로 SFT 모델"로 보면 된다. 사실 질문에는 thinking 모델이 과하고, 카파시도 80~90%는 4o를 쓴다.
- Gemini 2.0 Flash Thinking도 초기 실험판. 2025년 초 기준 Anthropic은 thinking 모델이 없었다.

### 4.5 AlphaGo와 Move 37 (2:42–2:48)

- AlphaGo 논문의 플롯: 인간 기보를 모방한 지도학습 모델은 최상위 기사 수준에서 **한계에 부딪히고**, 자기 대국 RL 모델은 이세돌을 넘어선다. 모방으로는 사람을 넘을 수 없다. 곡선은 비용 때문에 잘랐을 것이고 더 돌리면 더 올라갔을 것이다.
- Move 37: 인간이 둘 확률 1/10,000의 수. 돌이켜보면 명수. RL이 인간 분포를 벗어나 발견한 전략.
- LLM에서의 등가물은 아직 모른다. 사람이 못 만든 유추, 새로운 사고 전략, 영어가 아닌 자기만의 사고 언어일 수도 있다. 그러려면 **크고 다양한 문제 분포(연습문제 환경)**가 필요하고, 그것을 만드는 것이 현재 프론티어 연구다.

### 4.6 RLHF: 검증 불가능한 영역 (2:48–3:07)

- 수학·코드는 정답과 비교하면 되지만(박스 안 답 비교 또는 LLM judge), 농담·시·요약은 채점이 어렵다.
- 순진한 방법: 1,000업데이트 × 1,000프롬프트 × 1,000롤아웃 = 사람이 농담을 10억 번 평가. 불가능.
- 이 방법을 제안한 것은 당시 OpenAI 논문이고, 저자 다수가 지금 Anthropic 공동창업자다.
- RLHF의 트릭은 **간접화**: 사람이 5개 응답의 **순서**만 매긴다(점수보다 순서가 쉽다). 별도의 신경망(**reward model**)이 (프롬프트, 응답) → 0~1 점수를 내도록 순서와 일치하게 학습. reward model은 아마 Transformer지만 언어를 생성하지 않는 **채점 전용 모델**이다. 5,000개 정도만 사람이 보면 된다. 그 다음 reward model을 상대로 RL.
- **장점**: 검증 불가능 영역에도 RL을 쓸 수 있다. 경험적으로 모델이 좋아진다. 카파시의 가설은 **판별-생성 격차**: 사람에게 시를 쓰라는 것보다 5개 중 나은 것을 고르라는 것이 훨씬 쉬워서 더 정확한 신호를 얻는다.
- **단점**:
  1. 사람이 아니라 사람의 **손실 있는 시뮬레이션**에 대해 최적화한다.
  2. 더 치명적으로, RL은 **시뮬레이션을 게임하는 법을 찾아낸다**. 수백 스텝은 좋아지다가 갑자기 "the the the the"가 최고의 펠리컨 농담(점수 1.0)이 된다. adversarial example. 그것을 낮은 점수로 추가해도 무한히 새로운 것이 나온다. 그래서 RLHF는 수백 스텝에서 잘라야 한다.
- 결론: **"RLHF is not RL"**. 바둑이나 수학처럼 게임할 수 없는 보상은 무한히 돌릴 수 있고 Move 37이 나오지만, 게임 가능한 reward model은 "약간의 파인튜닝"에 그친다. 마법이 없다. GPT-4o는 RLHF를 거쳤지만 그런 의미다.

> minimind의 세 RL 스크립트를 이 기준으로 보면:
> - `train_dpo.py`: reward model 없이 선호쌍으로 직접 학습(RLHF의 변형).
> - `train_grpo.py`: 외부 reward model(`internlm2-1_8b-reward`) 점수 + 규칙 보상(길이, `</think>` 형식, 반복 페널티). 전부 게임 가능한 보상이다.
> - `train_agent.py`: 혼합이다. 도구 호출이 있으면 정답(`gt`) 적중이 최대 2.5/3.0으로 주된 항이고, 여기에 도구 호출 수 정렬, 미완성 감점, 반복 페널티가 붙는다. 도구 호출이 없으면 길이·형식 보상에 같은 reward model 점수를 더한다. 강의의 "순수 검증 가능 보상"에 해당하는 것은 `validate_gt_in_text` 항뿐이다. README도 이 스크립트 개발 중 reward hacking을 겪었다고 적고 있다.
> - 강의의 "몇백 스텝에서 잘라라"에 대응하는 코드 장치는 `train_grpo.py`의 `beta * per_token_kl` 항(reference 모델에서 멀어지면 페널티)이다.

## 5. 전망과 리소스 (3:07–3:31)

- **멀티모달**: 오디오(스펙트로그램 조각)와 이미지(패치)를 토큰화해 같은 컨텍스트에 섞으면 된다. 근본적 변화가 아니라 토큰 추가.
- **에이전트**: 지금은 작은 과제를 건네주는 수준. 오류 수정하며 장시간 일하는 능력은 아직. 공장의 human-to-robot 비율처럼 **human-to-agent 비율**을 말하게 될 것. Operator가 초기 사례.
- **Test-time training**: 현재 배포 후 파라미터는 고정이고 학습은 컨텍스트 안에서만(in-context). 사람은 자면서 파라미터를 갱신하는데 그 등가물이 없다. 컨텍스트를 늘리는 것만으로는 장기 멀티모달 과제를 못 버틴다. 새 아이디어가 필요.
- 리소스: LM Arena(DeepSeek이 MIT 라이선스 open weights로 3위에 오른 것이 "전례 없는" 일이라 평가. 다만 최근 게임되는 느낌이라 신뢰도 하락. 많이 쓰이는 Sonnet이 14위인 것이 예), AI News 뉴스레터(swyx), X. 모델 사용처: 독점 모델은 각 사 사이트, open weights는 together.ai, base 모델은 hyperbolic, 로컬은 LM Studio(증류·저정밀 버전).

### 마무리 (3:21–3:31)

- 질문 → 채팅 프로토콜 토큰으로 삽입 → 1차원 토큰 시퀀스 → 자동완성.
- 돌아오는 것: (SFT 모델) 라벨링 지침을 따르는 라벨러의 신경망 시뮬레이션. 2시간 걸릴 일을 즉시, 단 토큰당 고정 연산이라는 제약과 인지 차이를 안고서.
- (thinking 모델) 검증 가능한 문제에서 RL로 창발한 사고 전략이 더해짐. 그 전략이 창작 같은 검증 불가능 영역으로 **전이되는지는 미해결 질문**.
- 도구로 쓰고, 검증하고, 결과물은 본인이 책임진다.
